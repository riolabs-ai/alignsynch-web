AlignSynch v2 Docs, Plan and Drafts

The plan for illustrated user and admin docs for AlignSynch v2, laid out like the paperclipai/paperclip docs, with two sample pages.

AlignSynch v2 Docs

These docs explain every v2 design and feature for the people who use it. Each page opens with what the feature does for the person, walks through it with screenshots, and closes with acceptance notes and references for the build team.

The layout follows paperclipai/paperclip/docs: plain .md pages, a folder per audience, images under assets/<feature>/, and a Mintlify-schema docs.json that holds the navigation. A docs framework can render the folder later without changes.

Status (19 Nov 2026): all 51 pages in docs.json are written. Each page’s status follows the parity rule: Built only when the PR is merged on main (read-only check, main @ 601ce26), otherwise Planned with the issue or PR link. Claims about the shipped app cite file:line in a What’s Built Today table. MANIFEST.md lists every file on disk and where each screenshot came from. Nothing here changes the repo, the prototype or the bundles.

│   ├── account/               # (proposed) account menu, profile, delete account
│   └── admin/                 # CRUD & Permissions, Email Templates, admin rail

└── assets/
    ├── brand/                 # logo for docs.json
    └── <feature>/             # <name>-desktop.png, <name>-mobile.png

guides/shared/ and guides/account/ go beyond the folders that were asked for. They hold pages that would otherwise be copied into both the Initiator and Counterparty folders. If you’d rather not have them, those pages can move into guides/initiator/ and guides/counterparty/, each with its own version.

Sections (one line each; full page lists are in docs.json)

Get Started - Introduction: what AlignSynch is, how to start a relationship, the six stages, and plans and the free trial.

Guides - Initiator: starting a relationship, inviting someone, and covering the membership. - Counterparty: for the person who was invited. These pages never mention a price, a trial or a card. - Both People: answering, results, Align, proposing changes, chat and leaving. - Account & Settings: the account menu, profile and password, and deleting your account (immediate, can’t be restored). - Admin: the Admin rail tools: CRUD & Permissions, Email Templates, and who sees the rail.

Reference - Stages 1–6: one page per stage: who acts, what each person sees, what moves it forward. - States & Status: every relationship state by role, the status chips (icon plus word) and the 1–5 scale. - Emails: each email by seat: when it’s sent, the subject and the body. - Copy & Glossary: the words we use, the retired ones, and the copy rules. - Changelog: what changed in these docs and which decision caused it.

Page format

Frontmatter: title and summary are required. The extra keys audience, status and sources are for us; renderers ignore them.

---
title: When a Relationship Pauses
summary: One sentence on what this does for the person.
audience: [Initiator]                 # Initiator, Counterparty, Visitor, Admin
status: Built | Designed | Prototype Only | Planned
sources:
  - bundle: spec-design-v2-bundles/03-…/reference/
  - prototype: assessment.html?state=paused
---

Body, in order: opening paragraph (the value, in the person’s words) → At a Glance → How It Works (numbered, illustrated steps) → Good to Know → For the Build Team (acceptance checklist, locked rules, open deltas) → References (every shot with its source label and original path).

Wording is plain, warm and short. Labels are Title Case and quoted exactly as they appear in the UI. Status is always icon plus word, and nothing is red. Counterparty pages never use the words price, trial, card or extension.

Status values: Built (merged, with the PR named) · Designed (approved bundle render) · Prototype Only (only in the served prototype) · Planned (decided in an issue or PR, with no screen).

Screenshots

Source priority: Bundle (spec-design-v2-bundles/NN/reference/) → QA (capture of the built app) → Spec (spec folders, repo assets) → Prototype (spec-design-v2-prototype/screens/, or the 18 Nov captures in box /workspace/alignsynch/out/new-surfaces-shots/). A lower tier is used only when the higher one is missing or out of date, and the page says why.

Files: - assets/<feature>/<name>-desktop.png (1280 px render) and <name>-mobile.png (390 px). - Copies only. Originals are never moved or edited, and each page’s References table names the original. - Full-page renders that are too tall are cropped, and the References table says which part was kept. - Links are relative (../../assets/relationship-pause/trial-ended-initiator-desktop.png). Mobile shots use <img width="320"> so they don’t fill the page.

How the existing specs were checked visually

  • Bundles 01–12 record acceptance as: approved reference/*.png renders, a Validation checklist in each IMPLEMENTATION-PROMPT.md (“Compare with reference/settings-*… no overflow at 390/1280”), exact Copy strings, Locked rules, axe 0, and repository checks. Requirement IDs are DESIGN-NOTES § numbers and the P0 #1–#11 list. The only row-level requirement register is crud-matrix.md (169 cells).
  • The reference images are the prototype. 163 of the 170 bundle reference PNGs are byte-identical to spec-design-v2-prototype/screens/, rendered by src/qa/check4.js. The other 7 (bundle 12 and patterns-1280) came from the same build. VERIFY.txt only checks that pages load with no errors or overflow. Nothing compares pixels. So “acceptance” means “matches the prototype”, and nothing independent (Figma, a mockup, a written visual requirement) stands behind it. The 2023 PDF mockups in reference/mockups/ are marked “inspiration, not instruction”.
  • Later calls (18 Nov) were written down as text only (## Later call in bundle 11’s prompt). No reference render was updated. The repo’s bundle 11 references date from #1137 (17 Nov), so they still show the 30-day deletion and the Notifications card.
  • Built app: there are no QA captures of v2. The atlases are v1.17–v1.20, and #1179 was flagged for shipping without 390/1280 shots.

Handoff

When the set is approved:

  1. Link check (every image and relative link resolves; every docs.json page exists) and copy lint (no red, Title Case, no price, trial or card in Counterparty pages).
  2. Pack as spec-docs-v2-YYYY-MM-DD.tgz beside the other specs, with a VERIFY.txt like the bundles have.
  3. Hand off with the other specs waiting to go out. Suggested repo home: docs/specs/v2-docs/ (Jaden’s call; nothing is pushed from here).
